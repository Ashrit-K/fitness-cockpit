# fitness-cockpit

Training, bodyweight and tape measurements in one page, rebuilt three times a
day by GitHub Actions from the Liftosaur MCP API and served on GitHub Pages:
**https://ashrit-k.github.io/fitness-cockpit/**

## Pipeline

Each stage reads files and writes files, so any of them can be run alone.

| Step | Reads | Writes |
| --- | --- | --- |
| `fetch.py` | Liftosaur MCP (Bearer auth) | `weights.json`, `measurements.json`, `history.json`, `custom_exercises.json` |
| `muscle_map.py` | built-in exercise list | `muscle_map.json` |
| `chart.py` | `weights.json` | `chart.png`, `stats.json` |
| `volume.py` | `history.json`, `muscle_map.json` | `chart_sets.png`, `chart_tonnage.png`, `chart_targets.png`, `volume_stats.json` |
| `report.py` | all of the above | `report.json` |
| `index.html` | `report.json` | the page — figures are drawn client-side in vanilla SVG |

`index.html` is hand-maintained and is not regenerated by the workflow.

## What it tracks

- **Weight** — daily weigh-ins, smoothed over 7 days because a single morning
  reading is the noisiest number on the page.
- **Tape** — shoulders, chest, waist, hips, neck and limbs, read weekly.
  Recorded in inches, normalised to cm so no arithmetic depends on the unit.
- **Shape ratios** — shoulder:waist, chest:waist, shoulder:chest, waist:hip.
  A ratio cancels its unit and holds still on a day the scale lies. Each one
  carries the error it inherits from both tape reads, and a move inside that
  band is reported flat rather than as progress.
- **Volume and strength** — effective sets per muscle group against MEV/MAV/MRV
  landmarks, tonnage, e1RM retention, and the current programme block.

## Schedule

`.github/workflows/update.yml` runs at 04:00, 09:30 and 13:30 UTC — 09:30,
15:00 and 19:00 IST — plus manual dispatch. The first run follows the morning
weigh-in; the others follow a late-morning or afternoon session.

## Setup

Repo secret `LIFTOSAUR_TOKEN` = Liftosaur MCP API key (`lftsk_...`).

## Tests

```
python -m pytest tests/ -q
```

The workflow runs these before it commits, so a bad parse fails the run rather
than publishing a broken page.
